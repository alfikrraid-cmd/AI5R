## Actions Taken

### 1. `MODULES/PUMP/WORKFLOWS/WF-LTSA-PUMP-REGISTRY-001.json`

Replaced the placeholder credential reference with the already-resolved reference used elsewhere in the same product for the same table:

```diff
- "id": "REPLACE_WITH_POSTGRES_CREDENTIAL_ID",
- "name": "LTSA Brain PostgreSQL"
+ "id": "hzgFaX04t1nL01vF",
+ "name": "Postgres account"
```

**Result: PASS.** No unresolved placeholder remains in this file. This also resolves Broken Feature B5 from `MWO-P-001-LTSA-Product-Audit.md` ("the one workflow with real DB logic ships with an unresolved placeholder credential") — recorded here as a recovery action, `MWO-P-001` left unmodified per the audit-trail instruction.

### 2. `BUILD-PACKS/BP-007-AI5R-WORKFLOW-GENERATOR/generate_workflows.py`

This is generator *source code*, not a deployed artifact — it produces new workflow JSON files each time it runs, so hardcoding a specific credential ID into the script is itself the wrong fix (it would silently bind every future generated workflow, for any module, to one specific credential). Instead, the credential id/name were extracted to module-level configuration read from environment variables, with the previous literal preserved only as a fallback default so behavior is unchanged for anyone not yet setting the variable:

```diff
+ import os
...
+ POSTGRES_CREDENTIAL_ID = os.environ.get(
+     "LTSA_BRAIN_POSTGRES_CREDENTIAL_ID", "REPLACE_WITH_POSTGRES_CREDENTIAL_ID"
+ )
+ POSTGRES_CREDENTIAL_NAME = os.environ.get(
+     "LTSA_BRAIN_POSTGRES_CREDENTIAL_NAME", "Postgres account"
+ )
...
  "credentials": {
      "postgres": {
-         "id": "REPLACE_WITH_POSTGRES_CREDENTIAL_ID",
-         "name": "Postgres account"
+         "id": POSTGRES_CREDENTIAL_ID,
+         "name": POSTGRES_CREDENTIAL_NAME
      }
  }
```

**Result: WARNING, not BLOCKER.** The hardcoded literal is now sourced from configuration (satisfies "ensure secrets are loaded only from environment/config" for this generator), but the *default* fallback is still the unresolved placeholder string — this is intentional (no real credential ID can be safely assumed for a generic, reusable generator that may target other modules/databases in the future), so any workflow generated by this script **without** `LTSA_BRAIN_POSTGRES_CREDENTIAL_ID` set will still need its output patched before deployment. This is now a deployment-configuration requirement, not a hardcoded defect.
